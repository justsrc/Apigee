# Policy fault codes

Mechanically extracted from the `## Error reference` section of each policy page in
`research/pages/`. Regenerate with `python3 research/build_error_index.py`.

Read this as an index, not as an answer. It tells you which policy owns a code and
roughly why it fires. Open the policy page before telling someone what happened, because
the cause text here is truncated.

**Several policy pages document the same code.** Where they agree on the HTTP status,
one status is shown and every page is listed under Source. Where they disagree, the
row lists every status and is marked CONFLICT, because the documented answers are
genuinely different and neither is more correct. Read the page for the policy you
are actually debugging. Do not treat a single status here as the answer.

## How to use this

1. Take the `errorcode` from the response body, not the `faultstring` prose. Google
   states the text can change between releases, so matching on it is fragile.
2. Look the code up above and note which policies document it. A code listed on
   several pages is not owned by one of them at random.
3. Open the page for the policy actually in the proxy and read the full cause before
   proposing a fix.
4. If a row says CONFLICT, the documentation disagrees about the HTTP status. Do not
   average the values and do not quietly pick one. Say which page documents which
   status and tell the reader the documented answers conflict.
5. If the code is absent here, the policy page may not have been fetched. Check
   `research/pages/` and re-run `research/fetch.sh` on the policy's doc path.

Coverage: 195 runtime codes, 116 deployment errors, 33 fault variables, from 335 fetched pages.

3 runtime code(s) are documented with conflicting HTTP statuses across
policy pages. They are listed below in full so the conflict stays visible rather
than being resolved by this script.

- `steps.oauth.v2.access_token_expired`: documented as HTTP 500, 401 on get-oauth-v2-info-policy, oauthv2-policy, set-oauth-v2-info-policy
- `steps.oauth.v2.invalid_access_token`: documented as HTTP 401, 500 on delete-oauth-v2-info, get-oauth-v2-info-policy, set-oauth-v2-info-policy
- `steps.oauth.v2.invalid_request-authorization_code_invalid`: documented as HTTP 401, 500 on delete-oauth-v2-info, get-oauth-v2-info-policy
