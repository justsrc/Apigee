--- BODY ---
We ran into this specifically during the creation of Shared Flows; however, unsure whether or not this affects other functions as well.  
When including current working directory dot slash `apigeecli apis create -n petstore -f ./test/petstore.yaml` the imported error shared flow will complain that it is unable to find the file ./sharedflows/shared-flow-name.yaml and fails to properly deploy into Apigee X.  

> This is where the dot slash ./ notation comes in. It means “Look in the current directory.” When you use ./, you tell Ubuntu or Fedora or SUSE or whatever Linux distribution you're using to look in the current directory for the command you wish to run, and completely ignore what's on the application PATH.

We've test from Mac and GO based containers and it fails using ./ notation.  This caused a significant amount of lost time for our team troubleshooting this.
