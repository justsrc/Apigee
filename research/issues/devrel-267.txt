Hi @RezaRahmati thanks for reporting this. Can you please check if this solves your issue. You can rerun the deploy.sh without having to clean up first.

I also added a small fix to provide some debug logging when this occurs. This is part of PR #269

### comment by danistrebel (association=COLLABORATOR) at 2021-05-05T05:55:13Z
Hi Reza, Uploading the shared flow via the UI is perfectly reasonable. 

If in the future you still wanted to use the KVM to hold your Service Account key it would require you call the KVM admin proxy.  Most likely the simplest way would be: 

1. add an additional hostname to your env group called: `10-21-94-2.nip.io` (your internal IP as hostname, see nip.io for how this works)
1. set your APIGEE_X_HOSTNAME variable to `10-21-94-2.nip.io`
1. Run the deploy again from the VM in your private network
