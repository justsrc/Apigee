--- BODY ---
When creating a shared flow with apigeecli, deploying fails if the shared flow was created with the shared flow path using `./` notation. For example:

If a shared flow is created like so:
```
apigeecli sharedflows create -n $SF_NAME -f $SF_PATH -t $GCLOUD_TOKEN -o $APIGEE_ORG
```
where
```
$SF_PATH="./fromscratch/sharedflowbundle"
```

Deployment will fail with the following error on the console:
```
Status: instance "us-east1" reported error repository.FailedToLoadFile: "Failed to load file : /sharedflows/fromscratch.xml"
```

However, if the path is defined like so:
```
$SF_PATH="fromscratch/sharedflowbundle"
```
The shared flow deploys successfully.

Note that in both cases, the create step is successful.
