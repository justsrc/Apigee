Hi Team,

I'm facing 2 warnings (screenshot below) from Apigee linter which seems to be false positive.

![Image](https://github.com/user-attachments/assets/d836d636-6301-42a0-93fd-19394351f70b)

We usually define the SSLInfo in the edge.json file in the target server section, hence the same is not declared again in the load balancer segment. Is it logically correct for the linter to expect the value for SSLInfo in the target connection?

On the 2nd warning, it seems linter is highlighting the "Missing MaxFailures element within LoadBalancer", but based on the anti-pattern scenarios best practices(point number 3 https://cloud.google.com/apigee/docs/api-platform/antipatterns/load-balancing-maxfailures) 

```
If there's some constraint such that only one TargetServer and if the HealthMonitor is not used, then don't specify MaxFailures in the LoadBalancer configuration.

The default value of MaxFailures is 0. This means that Apigee always tries to connect to the target for each request and never removes the target server from the rotation.
```
Could we add a use-case that if there is only one server in the load balancer then max-failure warning should be supressed?

Pratyush

### comment by DinoChiesa (association=COLLABORATOR) at 2025-06-03T00:52:10Z
Thanks for reporting these things and engaging in the discussion.  This is helpful. We want to do the right thing and make sure the linter  gives good advice. 

For "When using a LoadBalancer, the SSLInfo should be configured in the TargetServer, not under HTTPTargetConnection": this warning is issued by plugin TD006.  In fact this is the only thing TD006 does. I still think configuring SSLInfo in the TargetServer is  the right thing to do.  In other words, I think in general the recommendation is correct: specify SSLInfo in the TargetServer.  But the plugin isn't checking that. It's checking the proxy. (TargetEndpoint).  And it has no way to check the referred TargetServer - in other words it has no way to check that SSLInfo is configured in the TargetServer, per the recommendation.  The design of the plugin is sort of broken - it assumes that if there is an SSLInfo under HTTPTargetConnection, then it is NOT present in the TargetServer. But that  is not a valid assumption. 

OK, so what do we do about that?   I see some options.

1. Do nothing. Keep the warning _as is_ .  If people want to disable it, they can do so with the command-line switch (`-e TD006`), or a directive in the XML (`  <!-- apigeelint disable=TD006 --> `), or in the `.apigeelintrc` file.   This is ok, if mildly annoying. 
2. Modify the warning so that Apigeelint emits it in all cases in which there is a LoadBalancer, whether or not there is an SSLInfo under HTTPTargetConnection.  This is accurate advice ("you should put SSLInfo in your TargetServer") but , during a scan of the proxy definition is sort of the wrong place to _offer that advice_.  So this seems like a bad idea I think. 
3. Omit (or demote) the warning.  Drop TD006 from the list of built-in plugins, and relegate it to an example "External Plugin".  In other words it's disabled by default, and people will need to take action in order to enable it.   This might be the best option. 

That brings us to TD012, a related issue. The warning here is "TargetEndpoint HTTPTargetConnection should have exactly one SSLInfo".  This is a good idea, a good recommendation, (a) when not using a LoadBalancer, and (b) when using a LoadBalancer but not all of the targetservers have SSLInfo defined.  Apigeelint cannot check case (b), because TargetServers are not present in the proxy definition.  So, the right thing here seems to be , to alter TD012 so that it flags a missing SSLInfo if and only if there is no LoadBalancer.    

> Regarding the fact that this condition "also gets flagged in Advanced API Security..."  That seems like a bug in Adv API Sec.  We don't have control over that. I suggest you connect with Google support and file a bug.  Adv API Sec **IS** able to see the TargetServers, and so it WILL have the complete information to tell you whether you have SSLInfo configured appropriately or not, and it SHOULD issue warnings only when appropriate. 

Regarding TD015.  "Missing MaxFailures element within LoadBalancer".  I can modify it such that if there is only one server in the load balancer then apigeelint will not issue this warning.  

----

So this is what I propose for changes: 

1. Demote TD006 to an External Plugin. 
2. Modify TD012 to fire if and only if there is no LoadBalancer
3. Modify TD015 so that it does not complain about a missing MaxFailures if there is a single server.

What do you all think?
