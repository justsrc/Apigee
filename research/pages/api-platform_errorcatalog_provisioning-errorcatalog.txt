<p>This error catalog is intended to help troubleshoot and resolve common errors you may encounter when provisioning
  Apigee resources.  It provides detailed information about the errors that may be 
  returned in the UI or on the command line during provisioning.</p>
  
<p>The catalog includes the following information:
<ul>
  <li>The error code</li>
  <li>The error message</li>
  <li>The possible cause of the error</li>
  <li>Steps to resolve the error</li>
</ul>
  
<h2 id="errors-returned-during-provisioning" data-text="Errors returned during provisioning" tabindex="-1">Errors returned during provisioning</h2>

<p>API calls are made during the provisioning of Apigee resources, whether you are provisioning from 
  the <a href="https://cloud.google.com/apigee/docs/api-platform/fundamentals/ui-overview">Apigee UI in Cloud
     console</a> or the command line interface (CLI).  API calls made during provisioning, or to check
     provisioning status, can return errors under a variety of circumstances, including the following:
<ul>
  <li>Google Cloud billing is not enabled for the project</li>
  <li>Required APIs are not enabled for the project</li>
  <li>Region, peering range, or other networking configuration issues</li>
</ul>
  
<p>Usually, the error message will contain information that you can use to correct any issues,
  resolve the error, and unblock provisioning.</p>

<h2 id="error-format" data-text="Error format" tabindex="-1">Error format</h2>

<p>If the error is a common error listed in this catalog, there will be an error message displayed
  in the Apigee UI in Cloud Console.  For example:

  <div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
  {
    "error": {
      "code": "FAILED_PRECONDITION",
      "message": "Error finding one or more network address ranges to use for the Instance. Verify
       the network configuration provided for the Instance and try again."
      }
  }</pre></devsite-code>

<p>Use the message provided to search this reference for more information about possible causes of 
  the error and potential steps you can take to resolve the problem.</p>

<h2 id="common-errors" data-text="Common errors" tabindex="-1">Common errors</h2>  
  
<h3 id="ext-1001" data-text="Location does not have enough resources available" tabindex="-1">Location does not have enough resources available</h3>

<h4 id="error-message" data-text="Error message" tabindex="-1">Error message</h4>

<div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
location "[loc]" does not have enough resources available to fulfill the request. Try again later
or choose a different location</pre></devsite-code>

<h4 id="possible-cause" data-text="Possible cause" tabindex="-1">Possible cause</h4>

<p>This error may occur when a request is made to provision an Apigee instance in a zone or region
  where one or more resources is not available.  This error is not a result of any problems with the
  instance configuration.</p>

<h4 id="steps-to-resolve" data-text="Steps to resolve" tabindex="-1">Steps to resolve</h4>
  
<p>To resolve the error, you can choose to provision your instance in another region, or wait for
  the issue to be resolved (typically within a few hours).</p>

<h3 id="ext-1002" data-text="Validation failed for service networking " tabindex="-1">Validation failed for service networking </h3>
  
<h4 id="error-message" data-text="Error message" tabindex="-1">Error message</h4>

<p>You will see an initial network validation error message, which may be followed by one or more
  of the following detailed error messages:

<div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
generic::failed_precondition: validation failed for service networking for network "[network]",
COMPUTE_API_NOT_ENABLED

generic::failed_precondition: validation failed for service networking for network "[network]",
RANGES_DELETED_LATER

generic::internal: error validating service networking consumer config for network "[network]":
This API method requires billing to be enabled. Please enable billing on project [project] by visiting
... then retry.</pre></devsite-code>

<h4 id="possible-cause" data-text="Possible cause" tabindex="-1">Possible cause</h4>

<p>This error may occur if the pre-provisioning validation of your network configuration fails.</p>

<h4 id="steps-to-resolve" data-text="Steps to resolve" tabindex="-1">Steps to resolve</h4>

<p>The following table lists actions you can perform to resolve these error messages:
  
<table>
  <tr>
    <td style="background-color: #f5f5f5">message
    </td>
    <td style="background-color: #f5f5f5">Steps to resolve
    </td>
  </tr>
  <tr>
    <td style="background-color: null">COMPUTE_API_NOT_ENABLED
    </td>
    <td style="background-color: null"><a href="https://cloud.google.com/apis/docs/getting-started#enabling_apis">Enable the Compute Engine API</a>.
    </td>
  </tr>
  <tr>
    <td style="background-color: null">RANGES_DELETED_LATER
    </td>
    <td style="background-color: null"><a href="https://cloud.google.com/vpc/docs/subnets#valid-ranges">Confirm that the provided IP ranges are valid.</a>
    </td>
  </tr>
  <tr>
    <td style="background-color: null">Require billing to be enabled ...
    </td>
    <td style="background-color: null"><a href="https://cloud.google.com/apis/docs/getting-started#enabling_billing">Confirm that billing is enabled on the project</a>.
    </td>
  </tr>
</table>
  
  
<h3 id="ext-1003" data-text="Couldn't find a free IP space of /22" tabindex="-1">Couldn't find a free IP space of /22</h3>

<h4 id="error-message" data-text="Error message" tabindex="-1">Error message</h4>

<div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
couldn't find a free IP space of /22 to launch an instance. Verify the peering ranges are available
as per https://cloud.google.com/apigee/docs/api-platform/get-started/install-cli#service-networking
and try again</pre></devsite-code>

<h4 id="possible-cause" data-text="Possible cause" tabindex="-1">Possible cause</h4>

<p>This error may occur during subnet creation, if an IP space of /22 is not available in the provided ranges.</p>

<h4 id="steps-to-resolve" data-text="Steps to resolve" tabindex="-1">Steps to resolve</h4>

<p>To resolve this error, confirm that the IP peering ranges provided <a href="/apigee/docs/api-platform/get-started/install-cli#service-networking">
  meet the requirements for subnet creation in service networking</a>. Then, retry the operation.</p>

<h3 id="ext-1004" data-text="Error in allocating IPs " tabindex="-1">Error in allocating IPs </h3>

<h4 id="error-message" data-text="Error message" tabindex="-1">Error message</h4>

<p>You may encounter one of the following error messages:

<div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
Error in allocating IPs to use for the Instance. Please verify the network configuration provided
for the Instance and try again.

Error in allocating IPs for ServiceAttachment.

Error finding one or more network address ranges to use for the Instance. Verify the network
configuration provided for the Instance and try again.</pre></devsite-code>

<p>You may also receive a detailed error message from the network client. For example:
<div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
Invalid resource usage: 'The resource 'projects/xxx' is already linked to another shared VPC host 
'projects/yyy'.</pre></devsite-code>

<h4 id="possible-cause" data-text="Possible cause" tabindex="-1">Possible cause</h4>

<p>This error may occur during Apigee instance creation when performing service networking operations,
such as creating a subnet or searching for a network range. In some cases, <a href="/service-infrastructure/docs/service-networking/getting-started">
Service Networking</a> may return an error message.</p>

<h4 id="steps-to-resolve" data-text="Steps to resolve" tabindex="-1">Steps to resolve</h4>

<p>Follow the instructions in the detailed message from Service Networking to resolve the error. You may need to:
  <ul>
    <li><a href="/apigee/docs/api-platform/get-started/console-configure-networking">Update the provided IP range allocations for the instance.</a> 
    <li>Address other Service Networking configuration issues.
    <li>Use another VPC network for instance configuration.</li>
  </ul>

<h3 id="ext-1005" data-text="KMS key permission denied" tabindex="-1">KMS key permission denied</h3>

<h4 id="error-message" data-text="Error message" tabindex="-1">Error message</h4>
<div></div><devsite-code><pre translate="no" dir="ltr" is-upgraded>
apigee service agent &lt;email&gt; cannot encrypt/decrypt with kms key &lt;keyID&gt;: PermissionDenied</pre></devsite-code>

<h4 id="possible-cause" data-text="Possible cause" tabindex="-1">Possible cause</h4>

<p>Before provisioning an Apigee instance, the KMS key provided is validated. This error indicates 
  that the Apigee Service Agent does not have the correct permissions required for the Cloud KMS CryptoKey
  Encrypter/Decrypter role on the provided key.</p>

<h4 id="steps-to-resolve" data-text="Steps to resolve" tabindex="-1">Steps to resolve</h4>

<p>Grant the Apigee Service Agent access to the provided KMS key.  You can find the command to grant access
  in Step 1(f) of <a href="/apigee/docs/api-platform/get-started/install-cli#create-org">Provision a paid
     org from the command line</a>.</p>

<h4 id="possible-cause" data-text="Possible cause" tabindex="-1">Possible cause</h4>

  Service Control.</p>

<h4 id="steps-to-resolve" data-text="Steps to resolve" tabindex="-1">Steps to resolve</h4>

   <code translate="no" dir="ltr">vpcServiceControlsUniqueIdentifier</code> to fix the VPC-SC configuration.</p>
