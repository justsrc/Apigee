This section lists all of the configuration properties that you can use to customize the runtime plane of your Apigee hybrid deployment.

**Note:** For instructions on how to add custom annotations, which are key/value maps used to attach metadata to Apigee hybrid Kubernetes pods, see [Custom annotations](/apigee/docs/hybrid/v1.17/customize-services#custom-annotations).

<div class="section expandable">

#### About configuration properties

You can override many configuration properties, if needed, by adding them to `HYBRID_ROOT_DIR``/overrides.yaml`.

**Tip:** Apigee provides a small set of sample configurations that you can use for further guidance. See [Sample overrides file](/apigee/docs/hybrid/v1.17/customize-services#sample-override-configurations).

For example, to change the replica count minimum and maximum for the MART service, you could add this stanza to `overrides.yaml`:

<div>

</div>

``` devsite-click-to-copy
mart:
    replicaCountMin: 3
    replicaCountMax: 6
```

You can also find these config properties and their default settings in `HYBRID_ROOT_INSTALL``/1.0.0/values.yaml`

For more information, see [`Manage runtime plane components`](/apigee/docs/hybrid/v1.17/customize-services).

Additionally, if you are configuring a deployment outside Google Cloud see [Step 7: Create the overrides](/apigee/docs/hybrid/v1.17/install-create-overrides) for information on setting these properties.

</div>

`cassandra.properties.externalEndpointsSync.secretRef`

Advanced

**Introduced in version:** 1.17.1

**Default value:** None

**Chart:** `apigee-datastore`

Setting `cassandra.properties.externalEndpointsSync` turns on *dynamic* endpoint sync for an external datastore. [`cassandra.properties.externalHost`](#cassandra-properties-externalhost) is required: the validating webhook allows `replicaCount: 0` only when externalHost is set, and the operator uses those addresses as the starting endpoints if it cannot read the remote endpoints before its first successful sync. When dynamic sync is enabled, the operator continuously reads the live, ready Cassandra endpoints from the remote cluster and mirrors them into the local cluster, so the runtime keeps tracking the remote Cassandra cluster as it scales up or down. When `externalEndpointsSync` is not set, the datastore uses the static addresses from [`cassandra.properties.externalHost`](#cassandra-properties-externalhost), unchanged.

`secretRef` is the name of a Kubernetes Secret in the datastore namespace that holds a `kubeconfig` key granting read-only access to the remote cluster's API. The operator uses these credentials to read the remote Endpoints. If `cassandra.properties.externalEndpointsSync` is set but `secretRef` is empty, every remote read fails, and the fail-open behavior that follows applies.

**Fail-open behavior:** if the operator cannot read the remote Endpoints (for example, the remote API server is unreachable or the credentials have expired), it keeps the last known-good endpoints instead of removing them, and never writes an empty endpoint list. This preserves existing connectivity, but it also means that a *sustained* failure stays hidden until the remote Cassandra topology next changes.

**Recommended alert:** Because fail-open masks a persistent failure, alert on the `EndpointSyncDegraded` status condition of the `ApigeeDatastore` resource. The operator sets it to `True` after three consecutive failed reads, with the reason `RemoteReadFailed` or `NoReadyRemoteEndpoints`, and sets it to `False` after a successful read. The operator stores the condition in the resource status, so it stays set when the operator restarts.

The operator also exports two metrics on its metrics endpoint, labeled with the `namespace` and `name` of the `ApigeeDatastore`:

- `external_endpoint_sync_last_success_timestamp`: the Unix time, in seconds, of the last successful read.
- `external_endpoint_sync_failures_total`: the number of failed reads.

You can also alert when the age of the last success exceeds a small multiple of [`intervalSeconds`](#cassandra-properties-externalendpointssync-intervalseconds). However, the operator doesn't report the timestamp metric again after a restart until a read succeeds. During a failure that continues across a restart, that alert stops firing, so use it together with the status condition.

`cassandra.properties.externalHost`

Basic

**Introduced in version:** 1.17.1

**Default value:** None

**Chart:** `apigee-datastore`

When set, marks this datastore as **external**: the Cassandra cluster runs outside this Kubernetes cluster. The value is a comma-separated list of remote Cassandra IP addresses (for example, `10.0.0.1,10.0.0.2`). The operator accepts only IP addresses. It ignores host names and DNS names, and it writes a warning to its log for each ignored entry. An address can have a `:``PORT` suffix, but the operator ignores the port and always uses port `9042`.

When `externalHost` is non-empty, the operator runs in external-datastore mode and doesn't create a local Cassandra <a href="https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/" class="external">StatefulSet</a> or PersistentVolumes, so [`cassandra.replicaCount`](#cassandra-replicacount) can be `0`. If you leave `externalHost` empty, the default in-cluster Cassandra behavior doesn't change.

**Note:** A valid [`cassandra.storage.storageSize`](#cassandra-storage-storagesize) (for example, `10Gi`) is still required in external-datastore mode, even with `replicaCount: 0`. The `ApigeeDatastore` validating webhook always validates `storageSize`, even though the operator doesn't create a PersistentVolume when Cassandra runs externally.

For dynamic tracking of the remote cluster's endpoints as it scales, see [`cassandra.properties.externalEndpointsSync`](#cassandra-properties-externalendpointssync-secretref). Do not confuse `externalHost` with [`cassandra.externalSeedHost`](#cassandra-externalseedhost) or [`cassandra.multiRegionSeedHost`](#cassandra-multiregionseedhost), which configure multi-region Cassandra ring seeding, a different mechanism.

`metrics.collector.envVars`

Basic

**Introduced in version:** 1.13

**Default value:** None

**Chart:** `apigee-telemetry`

Allows you to pass in and override environment variables in OpenTelemetry. For example, you can define `HTTP_PROXY`, `HTTPS_PROXY`, or `NO_PROXY` to have its requests pass through the proxy server.

The `HTTP_PROXY` variable can be defined as a string containing the host name, in the format:

<div>

</div>

``` devsite-enable-click-to-copy

metrics:
...
  envVars:
    HTTP_PROXY: '<host-name>'
```

for example:

<div>

</div>

```

  envVars:
    HTTP_PROXY: 'http://1.1.1.1:80'
```

The `HTTPS_PROXY` variable can be defined as a string containing the host name, in the format:

<div>

</div>

``` devsite-enable-click-to-copy

metrics:
...
  envVars:
    HTTPS_PROXY: '<host-name>'
```

for example:

<div>

</div>

```

  envVars:
    HTTPS_PROXY: 'https://1.1.1.1:80'
```

The `NO_PROXY` variable should be defined as a comma-separated string of host names, in the format:

<div>

</div>

``` devsite-enable-click-to-copy

metrics:
...
envVars:
  NO_PROXY: '<comma-separated-values>'
```

for example:

<div>

</div>

```

envVars:
  NO_PROXY: 'https://1.1.1.1:80, https://1.1.1.1:81'
```

Use `envVars: HTTP_PROXY`, `envVars: HTTPS_PROXY`, or `envVars: NO_PROXY` optionally when you have HTTP forward proxy enabled.

See <a href="https://opentelemetry.io/docs/collector/configuration/#proxy-support" class="external">Proxy support</a> in the OpenTelemetry documentation.

`metrics.proxyStackdriverExporter.podDisruptionBudget.minAvailable`

Advanced

**Introduced in version:** 1.17.0

**Default value:** None

**Chart:** `apigee-telemetry`

The minimum number of `proxyStackdriverExporter` pods that must stay available during a voluntary disruption, such as a node pool upgrade or node drain. This field sets the `minAvailable` field of the <a href="https://kubernetes.io/docs/concepts/workloads/pods/disruptions/" class="external">PodDisruptionBudget</a> for these pods. It takes either an integer number of pods (`1`) or a percentage string (`"50%"`).

`minAvailable` and `maxUnavailable` are mutually exclusive; set only one. The Apigee operator rejects setting both at once. If you set neither field, the Apigee operator still generates a PodDisruptionBudget for these pods, using `maxUnavailable: 1` by default.

For example, in `overrides.yaml`:

``` devsite-disable-click-to-copy
metrics:
  proxyStackdriverExporter:
    podDisruptionBudget:
      minAvailable: "50%"
```

## `watcher`

The `watcher` property is a required configuration property. The watcher is a process that watches for configuration changes and triggers their application to the runtime plane.

The following table describes the properties of the `watcher` object:

Allowed values are RuntimeDefault (to use the container runtime's default profile) or Unconfined (to apply no Seccomp restrictions). If not specified, no profile is applied by Apigee. See Configure Seccomp profiles for pod security . |
