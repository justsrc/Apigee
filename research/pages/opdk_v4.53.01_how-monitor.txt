## Monitoring Apache Qpid Broker-J

You can monitor Qpid Broker-J from the Qpid management console. This section explains how to access the console and use it to perform basic monitoring functions. For more detailed information on using the management console, see <a href="https://qpid.apache.org/releases/qpid-broker-j-8.0.6/book/Java-Broker-Management-Channel-Web-Console.html" class="external">Web Management Console</a> in the Apache Qpid documentation.

**Note:** We recommend you avoid making changes to the broker through the Qpid management console. If you intend to make broker configuration changes, we recommend you manage such changes using Edge properties files (referred to as *code with config*, or CwC) rather than using the console. If you do make broker changes using the management console, we recommend you test your changes on non-production environments before applying them to production. See also [How to configure Edge](/private-cloud/v4.52.01/how-configure-edge).

### Access the management console

The default management console port is 8090. To access the console on this default port, point your web browser to:

<div>

</div>

```
http://QPID_NODE_IP:8090
```

**Note:** If port 8090 is not open to access from your browser, you must extend or forward the port to a node with web browser support.

To log in to the console, use the default credentials set by Apigee or the ones set in the Edge configuration file. For details, see [Edge configuration file reference](/private-cloud/v4.52.01/edge-configuration-file-reference).

### Monitor queues and messages

In the left-navigation panel, navigate to **Java-Broker \> virtualhosts \> queues**. Select a queue to view its details in the main part of the UI. In the details view, you can see Queue Attributes and Statistics, including information on messages delivered, enqueued, message rates, and so on.

### View and download log files

In the left-navigation panel, navigate to **Java-Broker \> brokerloggers \> logfile**. In the main UI details view, you can view log file details and download log files.

### Using the Qpid management API

You can use the Apache Qpid Broker-J REST API to automate management tasks and monitor the broker. For details, see the <a href="https://qpid.apache.org/releases/qpid-broker-j-8.0.6/book/Java-Broker-Management-Channel-REST-API.html" class="external">Apache Qpid Broker REST API documentation</a>.

You can also use command line tools to monitor the broker. For example:

<div>

</div>

``` devsite-terminal
curl "QPID_NODE_IP":"8090"/api/latest/broker -u "USERNAME":"PASSWORD"
```

### Enable monitoring with SSL for Qpid

To provide additional security for monitoring and management, enable SSL on Qpid’s Management Portal and Qpid's Management APIs. Follow the guidelines below to provide a key and certificate.

Qpid provides an option for a File Keystore, which is enabled in Apigee. This type accepts the standard JKS keystore format understood by Java and Java tools such as **keytool**. It can also accept a PKCS12 keystore, which can be generated using tools like **OpenSSL**.

#### Keystore preparation

For generating keystores, see <a href="https://docs.oracle.com/javase/8/docs/technotes/tools/unix/keytool.html" class="external">Java Keytool Documentation.</a>

For generating PKCS12 keystores, see <a href="https://www.openssl.org/docs/" class="external">OpenSSL Documentation.</a>

**Note:** If you are using Edge for Private Cloud on a FIPS-enabled operating system, you should use a PKCS12 keystore to configure TLS on the Qpid Management Portal. PKCS12 keystores can be created using **OpenSSL** commands.

When you use a PKCS12 keystore, you need to add an additional configuration (in addition to the other standard configurations documented in this article):

<div>



## Apache ZooKeeper

### Check ZooKeeper status

1.  Ensure the ZooKeeper process is running. ZooKeeper writes a PID file to `opt/apigee/var/run/apigee-zookeeper/apigee-zookeeper.pid`.

2.  Test ZooKeeper ports to ensure that you can establish a TCP connection to ports 2181 and 3888 on every ZooKeeper server.

3.  Ensure that you can read values from the ZooKeeper database. Connect using a ZooKeeper client library (or `/opt/apigee/apigee-zookeeper/bin/zkCli.sh`) and read a value from the database.

4.  Check the status:

    <div>

    </div>

    ``` devsite-terminal
    /opt/apigee/apigee-service/bin/apigee-service apigee-zookeeper status
    ```

### Use ZooKeeper four-letter words

ZooKeeper can be monitored via a small set of commands (four-letter words) that are sent to the port 2181 using netcat (nc) or telnet.

For more info on ZooKeeper commands, see: <a href="https://zookeeper.apache.org/doc/r3.1.2/zookeeperAdmin.html#sc_zkCommands" class="external">Apache ZooKeeper command reference</a>.

For example:

- `srvr`: Lists full details for the server.
- `stat`: Lists brief details for the server and connected clients.

The following commands can be issued to the ZooKeeper port:

1.  Run the four-letter command ruok to test if server is running in a non-error state. A successful response returns "imok".

    <div>

    </div>

    ``` devsite-terminal
    echo ruok | nc host 2181
    ```

    Returns:

    <div>

    </div>

    ```
    imok
    ```

2.  Run the four-letter command, `stat`, to list server performance and connected clients statistics:

    <div>

    </div>

    ``` devsite-terminal
    echo stat | nc host 2181
    ```

    Returns:

    <div>

    </div>

    ``` devsite-click-to-copy
    Zookeeper version: 3.4.5-1392090, built on 09/30/2012 17:52 GMT

    /192.168.124.202:42185[1](queued=0,recved=1339,sent=1347)
    ```

    <div>
