In this part, you perform the following tasks:

Task

Description

[Prerequisites](/apigee/docs/hybrid/v1.17/prerequisites)

You need a Google Cloud project, a billing account, and the `gcloud` CLI.

If your installation will use [Data residency](/apigee/docs/api-platform/get-started/drz-concepts), Your project must have a [Subscription](/apigee/docs/api-platform/reference/subscription-entitlements) billing type and you must know in advance the regions where you plan to locate your control plane and user data.

[Step 1: Enable APIs](/apigee/docs/hybrid/v1.17/precog-enableapi)

Enable the APIs for Google Cloud services used by Apigee hybrid.

[Step 2: Create an Apigee organization](/apigee/docs/hybrid/v1.17/precog-provision)

Your [Apigee organization](/apigee/docs/api-platform/get-started/basic-concepts#organization) contains everything you create using Apigee, including API proxies and services, along with the resources needed to support them. Note that an Apigee organization is *not* the same as a Google Cloud organization.

[Step 3: Create an environment and environment group](/apigee/docs/hybrid/v1.17/precog-add-environment)

An [environment](/apigee/docs/api-platform/get-started/basic-concepts#environment) is an isolated software environment in which you can use Apigee's software tools to create and deploy API proxies. You can create multiple environments in an organization.

An [environment group](/apigee/docs/api-platform/get-started/basic-concepts#environment-group) is used to group one or more Apigee environments under a single hostname that can be used to call API proxies deployed to any environment in the environment group.

**Note:** If you plan to enable Google Cloud [Virtual Private Cloud (VPC) Service Controls](https://cloud.google.com/vpc-service-controls) with your Apigee hybrid installation, see [Using VPC Service Controls with Apigee and Apigee hybrid](/apigee/docs/api-platform/security/vpc-sc) for instructions before you proceed.
