**Note:** To deploy API proxies in environments enabled for [archive deployments](/apigee/docs/api-platform/fundamentals/environments-overview#deployment-types), see [Deploying and managing archives in an Apigee environment](/apigee/docs/api-platform/deploy/manage-archive-deployments).

You cannot invoke an API proxy until it has been deployed. After you create a new API proxy or make a change to an existing one, you can deploy it to your cluster.

When you create a new revision of an API proxy without changing its base path, then deploy it to an environment in which it's already deployed, the previous revision is undeployed and the new revision is deployed in its place.

**Note:** You cannot make incremental changes to an API proxy revision and redeploy that same revision to Apigee. To deploy changes to an API proxy, you must [save it as a new revision](/apigee/docs/api-platform/develop/ui-edit-proxy) and deploy it.

## Deploy an API proxy

Deploy an API proxy revision as described for one of the following methods.

<div class="ds-selector-tabs">

<div class="section">

### Apigee UI

To deploy an API proxy:

1.  In the Google Cloud console, go to the **Apigee <span aria-label="and then">\></span> Proxy Development <span aria-label="and then">\></span> API Proxies** page.

    <a href="https://console.cloud.google.com/apigee/proxies" class="button button-primary" target="console" data-track-name="consoleLink" data-track-type="tutorial" data-track-metadata-position="body">Go to API Proxies</a>

2.  Click the API proxy that you want to deploy. The UI displays the **Overview** page:

    <img src="/static/apigee/docs/api-platform/images/myproxy-in-overview.png" title="API proxy details" class="screenshot" alt="API proxy details including the deployment status per environment, the proxy endpoint details, and the target endpoint details." />

3.  To deploy your changes, click **Deploy** to display the **Deploy** dialog:

    <img src="/static/apigee/docs/api-platform/get-started/images/deploy-dialog.png" class="screenshot" style="width:70.0%" alt="Target endpoints selected in the Proxy Explorer." />

4.  Enter the following:
    - **Revision**: The revision number of the proxy you want to deploy.
    - **Environment**: The environment where you want to deploy the proxy.
    - **Service account** (optional): A <a href="https://cloud.google.com/iam/docs/service-accounts" class="external">service account</a> for the proxy.

5.  Click **Deploy**.

The UI begins the process of deploying the selected revision.

**Note:** It may take a few minutes for Apigee to deploy the new proxy.

When the proxy is deployed, the **Status** column in the **Deployments** section displays a green icon to show that revision 1 of the proxy is deployed.

<img src="/static/apigee/docs/api-platform/get-started/images/deployed-status.png" class="screenshot" style="width:50.0%" alt="Deployed proxy status icon" />

### Apigee API

The following sections provide examples of using the Apigee API to deploy API proxy revisions and list the deployments for your organization.

- [Create a deployment change report before deploying](#deploy-change-report)
- [Deploying an API proxy revision using the API](#deploy-api)
- [Listing deployments of an API proxy using the API](#list-deployments-api)

See also [Viewing deployment status](/apigee/docs/api-platform/deploy/ui-deploy-overview#viewing-deployment-status).

**Note:** Apigee restricts the number of deployment requests processed per second. If you attempt a large number of deployment requests simultaneously, you may see deployment failures due to timeout errors.

#### Create a deployment change report before deploying

Deploying a proxy in more than one environment in the same environment group may lead to undefined behavior. To determine whether this will occur, you can generate a report using the [`generateDeployChangeReport`](/apigee/docs/reference/apis/apigee/rest/v1/organizations.environments.apis.revisions.deployments/generateDeployChangeReport#google.cloud.apigee.v1.DeploymentService.GenerateDeployChangeReport) method as follows:

<div>

</div>

``` devsite-terminal

curl "https://apigee.googleapis.com/v1/organizations/$ORG/environments/$ENV/apis/$API/revisions/$REV/deployments:generateDeployChangeReport" \
-X POST \
-H "Authorization: Bearer $TOKEN"
```

This returns a [deployment change report](/apigee/docs/reference/apis/apigee/rest/v1/DeploymentChangeReport) that warns you if a base path in the proxy you want to deploy will not receive traffic due to an existing deployment that is already using that base path.

#### Deploying an API proxy revision using the API

To deploy an API proxy revision, use the following API call:

<div>

</div>

``` devsite-terminal
curl "https://apigee.googleapis.com/v1/organizations/$ORG/environments/$ENV/apis/$API/revisions/$REV/deployments" \
  -X POST \
  -H "Authorization: Bearer $TOKEN"
```

Where `$TOKEN` is set to your OAuth 2.0 access token, as described in [Obtaining an OAuth 2.0 access token](/apigee/docs/api-platform/get-started/api-get-started#oauth20). For information about the `curl` options used in this example, see [Using curl](/apigee/docs/api-platform/get-started/api-get-started#curl). For a description of environment variables you can use, see [Setting environment variables for Apigee API requests](/apigee/docs/api-platform/get-started/api-get-started#api-environment-variables).

**Key Point:** If an existing API proxy revision is deployed, set the `override` query parameter to `true`. In this case, Apigee deploys the new revision fully before undeploying the existing revision, as described in [Zero-downtime deployment](/apigee/docs/api-platform/deploy/ui-deploy-overview#zero-downtime-deployment).

The following shows an example of the response output. In this example, revision `1` of the `helloworld` API proxy was deployed successfully to the `test` environment:

<div>

</div>

```
{
  "environment": "test",
  "apiProxy": "helloworld",
  "revision": "1",
  "deployStartTime": "1559149080457"
}
```

For more information, see [Deploy API proxy revision API](/apigee/docs/reference/apis/apigee/rest/v1/organizations.environments.apis.revisions.deployments/deploy).

#### Listing deployments using the API

To list all deployments of API proxies and shared flows for your organization, enter the following API call:

<div>

</div>

``` devsite-terminal
curl "https://apigee.googleapis.com/v1/organizations/$ORG/deployments" \
  -X GET \
  -H "Authorization: Bearer $TOKEN"
```

Where `$TOKEN` is set to your OAuth 2.0 access token, as described in [Obtaining an OAuth 2.0 access token](/apigee/docs/api-platform/get-started/api-get-started#oauth20). For information about the `curl` options used in this example, see [Using curl](/apigee/docs/api-platform/get-started/api-get-started#curl). For a description of environment variables you can use, see [Setting environment variables for Apigee API requests](/apigee/docs/api-platform/get-started/api-get-started#api-environment-variables).

**Key Point:** When viewing a list of deployments, deployment status will not be provided. To view deployment status for an individual API proxy revision, see [Viewing deployment status](/apigee/docs/api-platform/deploy/ui-deploy-overview#viewing-deployment-status).

To deploy an API proxy revision, use the following `gcloud` command:

<div>

``` devsite-terminal

```

In this case, Apigee deploys the new revision fully before undeploying the existing revision, as described in [Zero-downtime deployment](/apigee/docs/api-platform/deploy/ui-deploy-overview#zero-downtime-deployment).

The following shows an example of the response output. In this example, revision `1` of the `helloworld` API proxy was deployed successfully to the `test` environment:

</div>

For more information, see [Deploy API proxy revision CLI](/sdk/gcloud/reference/alpha/apigee/apis/deploy).

## Troubleshooting

If you are unable to deploy your API proxy, check to see if one of the following common scenarios may apply.

### Naming restrictions for environment groups

If the name of your environment group does not comply with naming restrictions your proxy will not deploy. In some cases, it is possible to create an environment group and add environments to it without having to meet these restrictions. However, this will prevent proxy deployment.

See [Creating environment groups](/apigee/docs/api-platform/fundamentals/environmentgroups-working-with#groups) for a description of naming guidelines and restrictions.

### Environment created with a previously used environment name

If you create an environment with the same name as an environment that was previously deleted, your proxy will not deploy. For example, if you created an environment named `prod-1` after previously creating and deleting a `prod-1` environment, you will need to remove it. You can use the following steps to resolve this issue:

1.  Detach the `prod-1` environment from your environment group using the [API](/apigee/docs/reference/apis/apigee/rest/v1/organizations.instances.attachments/delete).
2.  Delete the `prod-1` environment using the [API](https://cloud.google.com/apigee/docs/reference/apis/apigee/rest/v1/organizations.environments/delete).
3.  Create a new environment. For example, `prod-2`.
4.  Attach the new `prod-2` environment to your environment group using the [API.](/apigee/docs/reference/apis/apigee/rest/v1/organizations.instances.attachments/create)

**Note:** To resolve deployment issues, see [deployment errors](/apigee/docs/api-platform/troubleshoot/playbooks/deployment/apigee-serving-cert-not-found-or-expired). For policy related issues, see [policy errors](/apigee/docs/api-platform/troubleshoot/policies/introduction).
