**Upgrading:** If you are upgrading to Apigee hybrid version 1.17.1, see [Upgrading Apigee hybrid](/apigee/docs/hybrid/v1.17/upgrade) for instructions. If you are performing a new installation, continue with the configurations described below.

This step explains how to create the cluster in which you will run Apigee hybrid. The instructions vary depending on the platform in which you are running hybrid. Before you begin, make sure to review the following information:

- [Minimum cluster configurations](/apigee/docs/hybrid/v1.17/cluster-overview)
- [Configuring dedicated node pools](/apigee/docs/hybrid/v1.17/configure-dedicated-nodes)
- [Configure Cassandra for production](/apigee/docs/hybrid/v1.17/cassandra-production)
- [Configuring authentication for Cassandra](/apigee/docs/hybrid/v1.17/cassandra-tls)
- [StorageClass configuration](/apigee/docs/hybrid/v1.17/cassandra-config)
- [Secure ports usage](/apigee/docs/hybrid/v1.17/ports)

**Note:** You can create a new, dedicated cluster for Apigee hybrid or you can install it in a cluster that is running other workloads. Creating a dedicated cluster for Apigee hybrid adds isolation and simplifies the overall effort required to maintain the cluster and its Apigee hybrid workloads.

If you install Apigee hybrid in a cluster running other workloads, you need to upgrade and maintain your cluster at the versions and features required in common for Apigee hybrid and for your other workloads. You may want to develop a plan to migrate one or more workloads if conflicts arise between supported versions and requirements.

The remainder of the installation instructions assume you are installing on a dedicated cluster.

### GKE

## Create a cluster on GKE

These steps explain how to configure and create a GKE cluster in your Google Cloud project.

**Caution:** Apigee does not support [GKE Sandbox](/kubernetes-engine/docs/concepts/sandbox-pods) or <a href="https://github.com/google/gvisor" class="external">gVisor for hybrid installations on GKE</a>.

Apigee recommends creating a **regional cluster** rather than a **zonal cluster**. If you are unfamiliar with the distinction between regions and zones, see [Regions and zones](/compute/docs/regions-zones). The available regions are listed in [Available regions and zones](/compute/docs/regions-zones#available). Just be aware that, for example, `us-west1` is a valid region name, while `us-west1-a` is a zone in the region.

1.  Make sure you are using a version of GKE that is supported for hybrid version 1.17.1. See [Apigee hybrid supported platforms and versions](https://docs.cloud.google.com/apigee/docs/hybrid/supported-platforms).

2.  Ensure the clocks on all nodes and application servers are synchronized with Network Time Protocol (NTP), as explained in the [Prerequisites](https://docs.cloud.google.com/apigee/docs/hybrid/v1.17/prerequisites). The Cassandra database relies on Network Time Protocol (NTP) synchronization to maintain data consistency. If you plan to install hybrid into multiple regions, make sure they are synchronized with NTP across all regions.

3.  (GKE private clusters only), If you are creating a private cluster on GKE, add a firewall rule to allow port 9443 for communication between GKE master nodes and GKE worker nodes and to allow the GKE masters to access Apigee mutating webhooks. Follow the procedure in [Adding firewall rules for specific use cases](/kubernetes-engine/docs/how-to/private-clusters#add_firewall_rules) in the Google Kubernetes Engine documentation. For more information see [Private clusters in GKE](/kubernetes-engine/docs/concepts/private-cluster-concept).

    You do not need to add this rule if you are creating a standard or public cluster.

4.  Create a **standard** cluster by following the instructions at [Create a regional cluster with a multi-zone node pool](/kubernetes-engine/docs/how-to/creating-a-regional-cluster#create-regional-multi-zone-nodepool). It's okay to create the cluster with just the default node pool. You will configure and create the required Apigee hybrid node pools in the next step.

    **Important**: Create a standard cluster instead of an Autopilot cluster. Apigee hybrid does not support Autopilot clusters, because Autopilot clusters do not support custom node pools. If you are using the Google Cloud console UI, make sure to select **SWITCH TO STANDARD CLUSTER**. <img src="/static/apigee/docs/hybrid/v1.17/images/create-cluster-switch-to-standard-cluster.png" title="Create cluster - switch to standard cluster" class="screenshot" alt="Create cluster screen heading showing Switch to Standard Cluster choice." />

    **Tip:** If you are not creating your cluster in the default network, follow the instructions in [Creating a cluster in an existing subnet](/kubernetes-engine/docs/how-to/alias-ips#creating_cluster)

    Go to the next step only after the cluster creation completes successfully.

5.  Create two node pools by following the instructions in [Add and manage node pools](/kubernetes-engine/docs/how-to/node-pools). Be sure to configure the node pools with the minimum requirements listed in the table below.

    <div class="section expandable">

    <span class="exw-control expand-control"></span>
    #### What you need to know about node pools

    **Note:** We recommend you use the names `apigee-data` and `apigee-runtime` for the node pools. Apigee hybrid recognizes these names by default. If you do not want to use the default names, additional configuration is required later when you configure the cluster for Apigee hybrid. For more information, including instructions for changing the default node pool names by editing your cluster configuration file, see [Using the default nodeSelectors](https://docs.cloud.google.com/apigee/docs/hybrid/v1.17/configure-dedicated-nodes#using-the-default-nodeselectors).
    We recommend you review the following information about node pools and node pool configuration before continuing:

    - [About node pools](https://docs.cloud.google.com/apigee/docs/hybrid/v1.17/cluster-overview#about-node-pools)
    - [Cassandra network requirements](https://docs.cloud.google.com/apigee/docs/hybrid/v1.17/cluster-overview#cassandra-network-requirements)

    </div>

    **Minimum node pool requirements**

    Be sure to satisfy these minimum requirements when creating the node pools. Be sure to select the value for **Production** or **Non-prod** (test or demo) depending on the the Apigee hybrid installation you are building. **Non-prod** installations are suitable for testing and demonstration but not sufficeint for production traffic. If you are using the Google Cloud console, be sure to configure both the **Node pool details** and **Nodes** sections.

    **Note:** The node pool configuration values described in the following table represent *minimum* values. This minimum configuration is suitable for testing; however, based on your needs, you can upsize the nodes now or in the future. For information on managing cluster nodes, see <a href="/kubernetes-engine/docs/how-to/node-pools" class="external">Add and manage node pools</a>.

    | Node pool name | Description | Minimum nodes | Production Minimum machine type | Non-prod Minimum machine type |
| --- | --- | --- | --- | --- |
| apigee-data | A stateful node pool used for the Cassandra database. | 1 per zone (3 per region) | e2-standard-8 (8 vCPU, 32 GB memory) | e2-standard-4 (4 vCPU, 16 GB memory) |
| apigee-runtime | A stateless node pool used by the runtime message processor. | 1 per zone (3 per region) | e2-standard-8 (8 vCPU, 32 GB memory) | e2-standard-4 (4 vCPU, 16 GB memory) |

    For more details about node pool configuration see [Configure dedicated node pools](/apigee/docs/hybrid/v1.17/configure-dedicated-nodes).

6.  (Optional) If you wish, you can delete the `default` node pool. See <a href="/kubernetes-engine/docs/how-to/node-pools#deleting_a_node_pool" class="external">Delete a node pool</a>.

7.  If you haven't already, create the following environment variables. These variables are used in the following gcloud commands.

    ### Linux / MacOS

    <div>

    </div>

    ``` devsite-click-to-copy
    export CLUSTER_LOCATION="YOUR_CLUSTER_LOCATION"
    export PROJECT_ID="YOUR_PROJECT_ID"
    ```

    </div>

    <div class="section">

    ### Windows

    <div>

    </div>

    ``` devsite-click-to-copy
    set CLUSTER_NAME="YOUR_CLUSTER_NAME"
    set CLUSTER_LOCATION=YOUR_CLUSTER_LOCATION
    set PROJECT_ID=YOUR_PROJECT_ID
    ```

    </div>

    Where:

    - **`CLUSTER_NAME`**: The name of your cluster.
    - **`CLUSTER_LOCATION`**: The region (for regional clusters) or the zone (for zonal clusters) in which you created your cluster, for example `us-west1` or `us-west1-a`.
    - **`PROJECT_ID`**: Your Google Cloud project ID.

8.  Verify the node pool configurations:


9.  Make sure your cluster is set as the default cluster for `kubectl` by getting the

    `gcloud` credentials of the cluster you just created:

    ### Regional clusters

    <div>

    <div>

    ``` devsite-terminal

    ```

    </div>

    See [Set a default cluster for kubectl commands](/kubernetes-engine/docs/how-to/cluster-access-for-kubectl#default_cluster_kubectl).

10. Configure [persistent solid state disk (SSD)](/compute/docs/disks#pdspecs) storage for Cassandra. We do not support using <a href="/compute/docs/disks#localssds" class="external">local SSDs</a>. For more information, see <a href="https://kubernetes.io/docs/tasks/administer-cluster/change-default-storage-class/" class="external">Change the default storage class</a> in the Kubernetes documentation.

    1.  Get the name of the current default StorageClass:

        <div>

        </div>

        ``` devsite-terminal
        kubectl get sc
        ```

        For example:

        <div>

        </div>

        ``` devsite-click-to-copy
        kubectl get sc
        NAME                    PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
        premium-rwo             pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
        standard                kubernetes.io/gce-pd    Delete          Immediate              true                   15h
        standard-rwo (default)  pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
        ```

    2.  Describe the StorageClass named `standard-rwo`. Note that its type is `pd-balanced`:

        <div>

        </div>

        ``` devsite-terminal
        kubectl describe sc standard-rwo
        ```

        For example:

        <div>

        </div>

        ``` devsite-click-to-copy
        kubectl describe sc standard-rwo
        ```

        <div>

        </div>

        ```
        Name:                  standard-rwo
        IsDefaultClass:        Yes
        Annotations:           components.gke.io/layer=addon,storageclass.kubernetes.io/is-default-class=false
        Provisioner:           pd.csi.storage.gke.io
        Parameters:            type=pd-balanced
        AllowVolumeExpansion:  True
        MountOptions:          <none>
        ReclaimPolicy:         Delete
        VolumeBindingMode:     WaitForFirstConsumer
        Events:                <none>
        ```

    3.  Create a new file called `storageclass.yaml`.

    4.  Add this code to the file. Note that the name of the new storage class is `apigee-sc`. You can use any name you like. Also, note that the storage type is `pd-ssd`:

        <div>

        </div>

        ``` devsite-click-to-copy
        ---
        kind: StorageClass
        apiVersion: storage.k8s.io/v1
        metadata:
          name: "apigee-sc"
        provisioner: kubernetes.io/gce-pd
        parameters:
          type: pd-ssd
          replication-type: none
        volumeBindingMode: WaitForFirstConsumer
        allowVolumeExpansion: true
        ```

    5.  Apply the new StorageClass to your Kubernetes cluster:

        <div>

        </div>

        ``` devsite-terminal
        kubectl apply -f storageclass.yaml
        ```

    6.  Execute the following two commands to change the default StorageClass:

        <div>

        </div>

        ``` devsite-terminal
        kubectl patch storageclass standard-rwo \
        -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
        ```

        <div>

        </div>

        ``` devsite-terminal
        kubectl patch storageclass apigee-sc \
        -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
        ```

    7.  Execute this command to verify that the new default StorageClass is called `apigee-sc`:

        <div>

        </div>

        ``` devsite-terminal
        kubectl get sc
        ```

        For example:

        <div>

        </div>

        ``` devsite-click-to-copy
        kubectl get sc
          NAME                  PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
          apigee-sc (default)   kubernetes.io/gce-pd    Delete          WaitForFirstConsumer   true                   14h
          premium-rwo           pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
          standard              kubernetes.io/gce-pd    Delete          Immediate              true                   15h
          standard-rwo          pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
        ```

    For more information about Workload Identity Federation for GKE, see [Enable Workload Identity Federation for GKE](/kubernetes-engine/docs/how-to/workload-identity#enable).

6.  Configure [persistent solid state disk (SSD)](/compute/docs/disks#pdspecs) storage for Cassandra. We do not support using <a href="/compute/docs/disks#localssds" class="external">local SSDs</a>. For more information, see <a href="https://kubernetes.io/docs/tasks/administer-cluster/change-default-storage-class/" class="external">Change the default storage class</a> in the Kubernetes documentation.

    1.  Get the name of the current default StorageClass:

        <div>

        </div>

        ``` devsite-terminal
        kubectl get sc
        ```

        For example:

        <div>

        </div>

        ``` devsite-click-to-copy
        kubectl get sc
          NAME                    PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
          premium-rwo             pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
          standard                kubernetes.io/gce-pd    Delete          Immediate              true                   15h
          standard-rwo (default)  pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
        ```

    2.  Describe the StorageClass named `standard-rwo`. Note that its type is `pd-balanced`:

        <div>

        </div>

        ``` devsite-terminal
        kubectl describe sc standard-rwo
        ```

        For example:

        <div>

        </div>

        ``` devsite-click-to-copy
        kubectl describe sc standard-rwo
        ```

        <div>

        </div>

        ```
        Name:                  standard-rwo
        IsDefaultClass:        Yes
        Annotations:           components.gke.io/layer=addon,storageclass.kubernetes.io/is-default-class=false
        Provisioner:           pd.csi.storage.gke.io
        Parameters:            type=pd-balanced
        AllowVolumeExpansion:  True
        MountOptions:          <none>
        ReclaimPolicy:         Delete
        VolumeBindingMode:     WaitForFirstConsumer
        Events:                <none>
        ```

    3.  Create a new file called `storageclass.yaml`.

    4.  Add this code to the file. Note that the name of the new storage class is `apigee-sc`. You can use any name you like. Also, note that the storage type is `pd-ssd`:

        <div>

        </div>

        ``` devsite-click-to-copy
        ---
        kind: StorageClass
        apiVersion: storage.k8s.io/v1
        metadata:
          name: "apigee-sc"
        provisioner: kubernetes.io/gce-pd
        parameters:
          type: pd-ssd
          replication-type: none
        volumeBindingMode: WaitForFirstConsumer
        allowVolumeExpansion: true
        ```

    5.  Apply the new StorageClass to your Kubernetes cluster:

        <div>

        </div>

        ``` devsite-terminal
        kubectl apply -f storageclass.yaml
        ```

    6.  Execute the following two commands to change the default StorageClass:

        <div>

        </div>

        ``` devsite-terminal
        kubectl patch storageclass standard-rwo \
          -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
        ```

        <div>

        </div>

        ``` devsite-terminal
        kubectl patch storageclass apigee-sc \
          -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
        ```

    7.  Execute this command to verify that the new default StorageClass is called `apigee-sc`:

        <div>

        </div>

        ``` devsite-terminal
        kubectl get sc
        ```

        For example:

        <div>

        </div>

        ``` devsite-click-to-copy
        kubectl get sc
          NAME                  PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
          apigee-sc (default)   kubernetes.io/gce-pd    Delete          WaitForFirstConsumer   true                   14h
          premium-rwo           pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
          standard              kubernetes.io/gce-pd    Delete          Immediate              true                   15h
          standard-rwo          pd.csi.storage.gke.io   Delete          WaitForFirstConsumer   true                   15h
        ```

When you have a cluster installed and running, go to the next step.
